What it does

The tool models identities, credentials, machines, services, permissions, and assets as a directed graph. Every edge is a real security relationship — a group membership, an ACL grant, a cached session, a trust between domains.

◉

Enumerate attack paths

From any compromised identity to any selected asset. Ranked by severity, annotated with MITRE techniques.

◍

Compute blast radius

Every node, credential, machine, and asset an identity can reach. Ranked by criticality and hop count.

◆

Find chokepoints

Nodes whose removal breaks one or more paths. The highest-leverage places to fix first.

⬢

Solve for the optimal fix

Minimum-cost set of edge cuts that disconnects source from every target. A real min-cut, not a heuristic.

▣

Track changes over time

Snapshot now, re-import later, and get a diff. New escalation edges, new memberships, the fixes that worked.

▤

Export a report

Markdown or print-ready HTML. Executive summary, top paths, mitigation plan, per-hop annotations.

How to use it

  1. Import Upload a security dataset. BloodHound SharpHound export, a ZIP of CSVs, a single JSON file, or a flat CSV of relationships.
  2. Review the mapping The profiler inspects every file's columns and decides what each table means. You see the interpretation before anything commits — with a confidence score. Low-confidence mappings are flagged.
  3. Analyse Click any identity in the graph to mark it as compromised. Shift-click any asset to select it as a target. Then run the analysis.
  4. Fix The min-cut solver proposes the minimum set of changes that sever every path. Not "here are 400 findings" — "change these 2 things."
  5. Track Snapshot now. Re-import next month. Diff the two to see what changed.

Reading the graph

Every node has a type and a criticality (1–5). Every edge has a kind and a direction. Here's the visual language:

Node types

IdentityUser, service account, group
CredentialPassword, hash, key, token
MachineWorkstation, server, VM
ServiceDaemon, app pool, process
PermissionRight, privilege, ACL
AssetDatabase, share, bucket — a crown jewel
DomainAD forest / trust boundary

Node size scales with criticality. Higher-criticality nodes render larger. Domains render as larger circles with a bright halo.

Edge types

Edges are colour-coded: dark red for "reverse" attacker edges (session dumps, cached admin material), grey for direct relationships. Dashed edges are cut in the current mitigation plan.

Understanding the numbers

Hops

How many graph edges a path traverses. A 3-hop path is 3 moves the attacker makes. Fewer hops = closer to your crown jewel.

Cost

Sum of edge weights. Each edge has a cost based on how much effort or tooling the attacker needs. Group membership is 0.3 (nearly free); a session dump is 1.2 (needs tooling and a live session). Lower cost = easier for the attacker.

Criticality

A number from 1 (low) to 5 (critical) on every node. Assigned from the source data, or defaulted when the data doesn't specify. Drives node size, blast-radius ordering, and which assets count as crown jewels.

Severity

A category for a whole path: TRIVIAL EASY MODERATE HARD. Blends hop count and required privilege. TRIVIAL means an attacker gets there in a few easy moves.

Required privilege

The highest privilege level any edge on the path requires. "admin" means the attacker needs admin-level access to some node. "logon" means only a valid logon.

Fix cost

Sum of the costs of the mitigations in a plan. A plan costing 2.0 is far cheaper to implement than one costing 20.0. Costs reflect how disruptive each change is — revoking a group membership is cheap, taking a server offline is expensive.

Supported file formats

The profiler auto-detects format. You do not need to conform to a specific schema — the tool figures out what each file means and shows you the interpretation before it commits.

BloodHound / SharpHound export (recommended)

The standard AD attack-path analysis format. Collect with SharpHound, upload the ZIP. The tool reads users.json, groups.json, computers.json, and domains.json, and parses the Aces field on every object — the real ACL graph. 

your-collection.zip
├── users.json       → IDENTITY nodes + ACL edges
├── groups.json      → GROUP nodes + MEMBER_OF edges
├── computers.json   → MACHINE nodes + sessions + local admins
└── domains.json     → Domain nodes + TRUST edges + DCSync rights

JSON environment

A single JSON document with metadata, nodes, and edges. 

{
  "metadata": { "name": "Example Enterprise" },
  "nodes": [
    { "id": "u1", "name": "Alice", "type": "IDENTITY", "criticality": 2 },
    { "id": "g1", "name": "Developers", "type": "GROUP", "criticality": 2 },
    { "id": "a1", "name": "Customer DB", "type": "ASSET", "criticality": 5 }
  ],
  "edges": [
    { "source": "u1", "target": "g1", "relationship_type": "MEMBER_OF" },
    { "source": "g1", "target": "a1", "relationship_type": "CAN_ACCESS" }
  ]
}

CSV bundle (ZIP)

A ZIP containing multiple CSVs. Every table is profiled independently. You don't have to name them anything specific — the profiler looks at column names, sample values, and file names together. 

environment.zip
├── identities.csv     id,name,type,criticality
├── groups.csv         id,group_name,type,criticality
├── memberships.csv    user_id,group_id
├── machines.csv       id,hostname,os,criticality
├── credentials.csv    id,name,credential_type,criticality
├── assets.csv         id,asset_name,criticality
└── permissions.csv    source,target,privilege_level,relationship_type

Any other structured data

The profiler recognises common synonyms. A column called principal is treated as a source reference. A column called resource is treated as a target. A column called permission is treated as a privilege level. Files whose meaning is unclear are flagged — nothing is guessed silently.

What a min-cut means

A min-cut is the minimum set of edges whose removal disconnects a source from every target. The engine computes this exactly using Dinic's max-flow algorithm over a flow network — one node per graph node, split in/out so we can cut nodes as well as edges.

The solver prefers actionable cuts. Edges that terminate at ASSET nodes are protected — the algorithm can't propose "disconnect DC01 from its own database" because that isn't a real change. Instead it looks for the group membership to revoke, the ACL to remove, the workstation to isolate.

Real-world example from a BloodHound export: a contractor could reach NTDS.dit through 16 distinct paths. The min-cut solver returned one edge — revoke Frank's membership in Domain Admins — costing 2.0. Every path severed.

Provenance & trust

Every edge in the graph is traceable back to the source file and row that produced it. Click any edge in the app and see:

  • Which file it came from
  • Which row of that file
  • The original column values
  • The mapping decision that produced it
  • Its origin: OBSERVED, DERIVED, or SIMULATED

Nothing is fabricated. If the source data doesn't contain a relationship, the graph doesn't contain it either. The engine prefers to report "unable to determine" over inventing an edge.

Limits & honesty

What this tool is, and what it isn't.

It is

  • A graph-reachability engine
  • A way to reason about identity relationships
  • A tool for finding the cheapest set of fixes
  • Deterministic and explainable

It isn't

  • A scanner that touches live systems
  • An exploitation tool
  • Proof that a path is exploitable in practice
  • A replacement for a red-team engagement

Every relationship in the graph comes from data you provided or from a documented graph rule (session dumping, cached admin material, trust traversal). Nothing is fabricated and nothing is confirmed by exploitation.
